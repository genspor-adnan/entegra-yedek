Hedef: Sağlık Bakanlığı Teleradyoloji (Teletıp) radyoloji verisini kılavuzdaki gibi görsün - istem (HL7 ORM), rapor (HL7 ORU), görüntü manifesti (KOS / XDS-I.b), doz (RDSR) ve görüntünün kendisi (Bakanlık WADO ile bizden çeker).
İş bölümü: mesajın içeriğini Gentegre üretir (Bakanlık profili, eksik kontrolü, accession / TCKN kuralı); Mirth taşır - kuyruk, yeniden deneme, ACK, arşiv, Bakanlık bağlantısı. Gentegre Teletıp'a doğrudan bağlanmaz; Bakanlık'ta tanıtılan IP Mirth sunucusunun IP'sidir. Sıra

  1. MWL - yazıldı (1301), commit bekliyor.
  2. Mirth kurulumu + K1 ORU: mevcut ORU kuyruğunun hedefi Mirth; ACK zinciri uçtan uca.
  3. ORM üretici (NW / XO / CA) + K1; teletip_gonderim tablosu + K4 + ekran 3/4/6.
  4. K2 KOS (Bakanlık jar'ı) + yeniden gönder.
  5. Public WADO + Bakanlık'a IP bildirimi (kurumun işi, biz test ederiz).
  6. K3 doz, sonra sorgu servisleri ve pano (ekran 2).

Açık karar

  • Mirth sürümü (karar, kullanıcı 11.11.2026: "mirth 4.5.2 kullanacağız"): Mirth Connect 4.5.2 - son açık kaynak sürüm (4.6+ NextGen ticari). Sürüm sabit; Mirth güncellemesi kendiliğinden yapılmaz. Java 17, varsayılan Derby yerine kurumun PostgreSQL'i (mesaj arşivi).
