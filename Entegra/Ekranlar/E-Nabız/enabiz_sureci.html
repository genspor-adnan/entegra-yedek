Tek cümlede: Klinik olaylar (kabul, muayene, reçete, tetkik, görüntüleme, sevk) paket olarak kuyruğa düşer, alanlar SKRS kodlarına çevrilip doğrulanır, zamanlayıcı USS servisine gönderir, yanıt paket üstünde saklanır; hatalı olan kök nedene (hekim kartı, klinik eşleme, kod listesi) yönlendirilir. Okuma yönü (hasta geçmişi) izinle, anlık, saklamadan.
Mockuplar: enabiz_gonderim_kuyrugu.html · enabiz_paket_karti.html · enabiz_ayarlar_esleme.html · enabiz_paket_listesi.html · enabiz_hasta_gecmisi.html · enabiz_veri_kalitesi.html

1. Akış

Klinik olay→ Paket üret (tetik)→ Alan çöz + SKRS eşle→ Doğrula (zorunlu alan / liste)→ Kuyruk→ Zamanlayıcı gönderir→ Yanıt: OK / hata→ Hata sınıfına göre tekrar / düzelt→ Kaynak iptal → silme paketi
#AdımNe olur
1TetikOlay tablolarındaki durum geçişi (başvuru kapandı, reçete imzalandı, rapor onaylandı) paket üretimini çağırır; enabiz_paket_turu.tetik_olay eşleşir ve tür aktifse paket açılır. Aynı kaynak için içerik hash'i aynıysa yeni paket üretilmez.
2Alan çözümlemeHer USS alanı kaynak kolondan okunur; SKRS listeli alanlar için yerel kod → SKRS kodu (kod_deger.skrs_kod ya da enabiz_kod_esleme). Sonuç enabiz_paket_alan'a satır satır yazılır.
3DoğrulamaPaket türünün zorunlu alan listesi + SKRS liste üyeliği + format (TCKN 11 hane, tarih). Eksik varsa durum eksik alan, kuyruğa girmez; sorun paket kartında kaynağa link ile gösterilir.
4GönderimZamanlayıcı (15 dk) bekleyenleri alır; XML üretir, USS'ye kimlikle gönderir; yanıt enabiz_gonderim'e, özet enabiz_paket'e. Başarılıysa USS paket kimliği saklanır.
5Hata yönetimiServis hatası (zaman aşımı, 5xx) → otomatik 5 tekrar. Veri hatası (kod pasif, alan boş) → kullanıcıya mesaj (Mesajlar modülü), düzeltince "kaynaktan yeniden üret". Yetki hatası → entegrasyon hesabı uyarısı.
6Güncelleme / silmeKaynak kayıt düzeltilirse (tanı değişti) güncelleme paketi, iptal edilirse silme paketi — ilk paketin USS kimliğiyle. Onaylı gönderim (elle).
7OkumaHasta geçmişi: hasta izni + hekim gerekçesi → USS okuma servisi; yanıt ekranda gösterilir, veri tabanına yazılmaz; yalnız enabiz_sorgu_log.
8İzlemeVeri kalitesi panosu: gönderim oranı, hata sınıfları, hekim skoru, eşlenmemiş kodlar; süre sınırı yaklaşan paketler.

4. SKRS listeleri — ek ihtiyaç

340 ile gelen listelere (cinsiyet, medeni hal, yabancı hasta türü, kan grubu, branş, sigortalı türü, il/ilçe, ülke) e-Nabız için eklenecekler:

  • KLİNİK KODU → departman.skrs_klinik_kod
  • HASTA KABUL TÜRÜ, GELİŞ ŞEKLİ, VAKA TÜRÜ, TABURCU ŞEKLİ, MUAYENE TÜRÜ → başvuru / muayene kod listeleri
  • ICD-10 (büyük liste, ayrı tablo icd10: kod, ad, ust_kod, cinsiyet kısıtı, aktif)
  • İLAÇ (barkod, ad, etken madde, aktif) — ayrı tablo ilac
  • SUT İŞLEM → hizmet.sut_kodu doğrulaması
  • SONUÇ BİRİMİ, TETKİK (lab modülüyle)
  • PERSONEL UNVAN → taraf_hekim.skrs_unvan

Mevcut SKRS senkronu (EntegrasyonUclari.SkrsListeleri) liste adı → yerel kod listesi eşlemesiyle çalışır; yeni listeler aynı diziye eklenir, büyük listeler (ICD-10, ilaç) tablo hedefli (SkrsTablolari) olarak.
