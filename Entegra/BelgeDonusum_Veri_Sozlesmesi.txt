3. ADIM SIRASI VE SORUMLULUK
-----------------------------
  ADIM                         OKUR                        YAZAR
  ---------------------------  --------------------------  -----------------------
  Uygula: JSON ac              @KaynaklarJson              #KaynakBaslik, #KaynakSatir,
                                                           #IzlemeSecim
  Uygula: BEGIN TRAN           -                           -
  Dogrula                      #KaynakBaslik, #KaynakSatir #KaynakSatir.Durum,
                                                           .StokYeterli, #Uyari
  Kaydet (Baslik+Satir)        #KaynakBaslik, #KaynakSatir #SatirEsleme
    -> sp_Api_Belge_Kaydet_Json
  IzlemeAktar                  #IzlemeSecim, #SatirEsleme  STOKIZLEME,
                                                           STOKIZLEMEDEPO,
                                                           #IzlemeSecim.YeniIzlemeId
  UretimAktar (415/420)        #SatirEsleme                FATURA (recete sarflari)
  Sonlandir                    #SatirEsleme                kaynak DURUM, durtme,
                                                           BELGEDONUSUMISLEM
  Uygula: COMMIT + sonuc       hepsi                       -

TRANSACTION SAHIBI YALNIZ ANA SP'DIR. Alt SP'ler BEGIN/COMMIT/ROLLBACK YAPMAZ.
Hata: alt SP THROW eder, ana SP CATCH edip XACT_STATE()<>0 ise ROLLBACK yapar
ve yapilandirilmis sonuc doner.

KAYDET'IN KENDI TRANSACTION'I: sp_Api_Belge_Kaydet_Json icinde BEGIN TRAN /
COMMIT var. Ic ice transaction'da COMMIT sayaci azaltir, gercek commit disarida
olur - guvenli. Ancak Kaydet XACT_ABORT ON + THROW kullaniyor: ic THROW dis
transaction'i da geri alir. Bu ISTENEN davranistir (tam rollback), fakat ana
SP'nin CATCH blogunda XACT_STATE() = -1 durumu ayrica ele alinmali.

HATA KODU ARALIKLARI (mevcut API ile ayni):
  51000-51099 girdi hatasi     51100-51199 yetki
  51200-51299 is kurali        51300-51399 es zamanlilik


4. IDEMPOTENCY - BELGEDONUSUMISLEM
-----------------------------------
ANA veritabaninda (GENDEPO'da DEGIL - synonym bagimliligi log ekraninda sorun
cikarmisti):

CREATE TABLE dbo.BELGEDONUSUMISLEM (
    ID              INT IDENTITY PRIMARY KEY,
    ISTEKID         UNIQUEIDENTIFIER NOT NULL,
    DONUSUMTURU     INT NOT NULL,
    KULLANICIID     INT NOT NULL,
    SUBEID          INT NOT NULL,
    DURUM           NVARCHAR(12) NOT NULL,   -- BASLADI | TAMAMLANDI | HATA
    HEDEFBASLIKID   INT NULL,
    HEDEFTUR        INT NULL,
    BASLAMATARIHI   DATETIME NOT NULL DEFAULT GETDATE(),
    BITISTARIHI     DATETIME NULL,
    SONUCJSON       NVARCHAR(MAX) NULL,
    HATAKODU        INT NULL);
CREATE UNIQUE INDEX UX_BELGEDONUSUMISLEM_ISTEKID ON dbo.BELGEDONUSUMISLEM(ISTEKID);

Ayni ISTEKID tekrar gelirse:
  TAMAMLANDI -> onceki SONUCJSON aynen dondurulur, hicbir sey yazilmaz
  BASLADI    -> 51300 "islem devam ediyor" (BASLAMATARIHI 5 dakikadan eskiyse
                terk edilmis sayilir ve yeniden denenir)
  HATA       -> yeni deneme SERBEST

HATA KAYDININ ROLLBACK SORUNU: SQL Server'da autonomous transaction yok. Ana
transaction rollback olunca HATA satiri da geri gider. COZUM: "BASLADI" satiri
transaction'dan ONCE ayri bir cagride yazilir (kendi kucuk transaction'i),
sonuc/hata guncellemesi de COMMIT/ROLLBACK'ten SONRA yapilir. Boylece izleme
kaydi her kosulda kalir.

7. STOK YETERSIZLIGI AKISI (Degerlendirme_2 madde 2.3)
-------------------------------------------------------
Varsayilan: bir satirda stok yetersizse TUM donusum reddedilir (51200), satir
sessizce ATLANMAZ. Yetersiz satirlar Uyarilar'da doner.
StokDurumKontrolKurali kullanici onayina izin veriyorsa uygulama onayi alir ve
AYNI istegi @SeceneklerJson.stokOnayi=true ile yeniden gonderir; bu durumda
donusum yapilir ve onay UYARILARJSON + islem kaydinda saklanir.
Bu MEVCUT DAVRANISTAN FARKLIDIR (bugun satir sessizce atlanip eksik belge
olusuyor) - K6 onay listesinde.

9. PG PARITESI
---------------
Bu sozlesme MSSQL icindir. PG karsiligi ayri faz:
  #temp tablolar        -> ON COMMIT DROP gecici tablo
  OUTPUT INSERTED.ID    -> RETURNING
  UPDLOCK/HOLDLOCK      -> SELECT ... FOR UPDATE
  XACT_ABORT/TRY-CATCH  -> plpgsql EXCEPTION
  fonksiyon icinde COMMIT/ROLLBACK YOK -> transaction sinirinin cagiran
    baglantida oldugu varsayilir
  PG'de FATURA/FATBASLIK/SIPARIS/STOKIZLEME uzerinde TRIGGER YOK; MSSQL'de
  trigger'a birakilan yan etkiler (stok durumu, fiyat, cari bakiye) PG
  fonksiyonunda ACIKCA yapilmali ya da once trigger'lar portlanmali.
