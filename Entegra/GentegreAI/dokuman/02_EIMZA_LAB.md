# Laboratuvar Sonuç Raporu — e-İmza Süreci

Mockup: `Ekranlar/Lab/lab_rapor_eimza.html`

## Bugün ne var, ne yok

Bugün lab tarafında **kriptografik imza yok**. Olan şey *onay damgası*:

| Aşama | Nerede | Ne yazılır |
|---|---|---|
| Teknik onay | `lab.teknik-onay` aksiyonu | onaylayan + zaman |
| Uzman onayı | `lab.onayla` | onaylayan + zaman |
| Muayene raporu imzası | `POST /api/muayene/rapor/{id}/imzala` | `durum=2`, `imza_zamani`, `imzalayan` |

Bu damga **kim onayladı** sorusunu cevaplar, **belge sonradan değişti mi** sorusunu cevaplamaz.
Nitelikli elektronik imza (NES) tam olarak ikincisi içindir: 5070 sayılı Kanun'a göre NES ile
imzalanmış belge ıslak imzayla aynı hukuki sonucu doğurur ve imza sonrası **bir bit bile
değişirse doğrulama düşer**.

## Neden gerekli

- Sonuç raporu hastaya ve dış kurumlara gidiyor; ıslak imza karşılığı bir güvence gerekiyor.
- e-Nabız'a giden rapor ile hastanın elindeki PDF'in **aynı** olduğu kanıtlanmalı.
- Bir yıl sonra "bu değer sonradan mı değişti" sorusu, imza + zaman damgasıyla kapanır.

## Süreç

```
numune kabul → çalışma → teknik onay → uzman onayı → E-İMZA → zaman damgası → e-Nabız
```

1. **Teknik onay** (teknisyen): cihaz sonucu doğru okundu mu. İmza yok.
2. **Uzman onayı** (uzman hekim): klinik değerlendirme, yorum, panik değer kararı. İmza yok.
3. **e-İmza** (uzman hekim): rapor **dondurulur**, PDF üretilir, imzalanır.
4. **Zaman damgası** (TSA): imzanın *ne zaman* atıldığı, imzalayanın saatine bırakılmaz.
5. **Dağıtım**: yalnız imzalı rapor e-Nabız'a, hastaya ve isteyen hekime gider.

**Kural:** imzalanan şey ekrandaki tablo değil, **raporun tamamıdır** — kurum anteti, hasta kimliği,
numune/çalışma zamanları, sonuç değerleri, referans aralıkları, yorum, imzalayan. Ekrandaki gridi
imzalamak, yarın referans aralığı değişince eski raporu farklı gösterir.

## İmza nasıl atılır (teknik)

Tarayıcı akıllı karta erişemez. Zincir şöyle:

```
Sunucu                         İmza Aracı (yerel)            Akıllı kart / token
  │ 1. PDF üret, SHA-256 özet    │                              │
  ├─────────── özet ────────────►│ 2. PIN sor                   │
  │                              ├──────── özet ───────────────►│ 3. özeti imzala
  │                              │◄─────── imza ────────────────┤    (özel anahtar KARTTA kalır)
  │◄────────── imza ─────────────┤                              │
  │ 4. imzayı PDF'e göm (PAdES)  │                              │
  │ 5. TSA'dan zaman damgası al  │                              │
  │ 6. doğrula, sakla, kilitle   │                              │
```

- **İmza aracı**: yerelde çalışan küçük bir uygulama (`127.0.0.1` üzerinde HTTPS). Java applet
  devri bittiği için standart yol budur.
- **Alternatif: mobil imza** — kart yerine GSM operatörü (Turkcell/Vodafone/TT). Kullanıcı telefonda
  onaylar; araç kurulumu gerekmez, imza sunucu üzerinden yürür.
- **Biçim**: **PAdES-T** (imza PDF'in içinde + zaman damgası). XAdES yalnız XML gerekirse.
- **Özel anahtar hiçbir zaman karttan çıkmaz**; sunucuya yalnız özet gider, imza geri gelir.

## Toplu imza

Bir uzman günde 100+ rapor onaylıyor; her rapor için PIN sormak sürdürülebilir değil.

- Seçilen raporlar **tek kart oturumunda** imzalanır, PIN bir kez sorulur.
- Oturum kısa ömürlüdür (ör. 2 dk / pencere kapanınca düşer).
- Her rapor **ayrı ayrı** imzalanır — "hepsini kapsayan tek imza" değil; biri iptal edilirse
  diğerleri etkilenmez.

## İmzadan sonra düzeltme: ek rapor (addendum)

İmzalı rapor **silinmez, değiştirilmez**. Düzeltme `v2` olarak açılır:

- ek raporda **neyin değiştiği ve gerekçesi zorunlu**,
- v2 de ayrıca imzalanır,
- hastanın elindeki v1 geçerliliğini korur; hangi sürümün ne zaman imzalandığı bellidir.

Bu, "sonucu düzelttik, eskisini sildik" davranışının kapısını kapatır.

## Panik değer

Panik değer bildirimi **imzayı beklemez**. Telefon bildirimi ve kaydı önce yapılır; imza raporu
resmîleştirir, hastanın hayatını kurtaran şey bildirimdir. Bildirilmemiş panik değerli rapor
toplu imza kuyruğuna girmez.

## Veri modeli (öneri)

`lab_sonuc` / rapor tablosuna değil, **ayrı bir imza tablosuna** yazılmalı — aynı yapı radyoloji,
muayene raporu ve reçete için de kullanılır:

```sql
create table public.belge_imza (
    id            integer primary key generated by default as identity,
    kaynak        varchar(30) not null,   -- 'lab_rapor' | 'radyoloji_rapor' | 'muayene_rapor'
    kayit_id      integer     not null,
    surum         smallint    not null default 1,   -- v1, v2 (addendum)
    ozet          varchar(64) not null,   -- imzalanan PDF'in SHA-256'sı
    imza_bicimi   varchar(20) not null,   -- 'PAdES-T'
    imzalayan_id  integer     not null,   -- taraf.id (hekim)
    sertifika_seri varchar(64),
    sertifika_bitis date,
    imza_zamani   timestamp   not null,   -- karttan gelen
    damga_zamani  timestamp,              -- TSA'dan gelen
    damga_kaynak  varchar(60),
    dosya_id      integer     not null,   -- imzalı PDF (doküman deposu)
    durum         smallint    not null default 1,   -- 1 geçerli · 2 iptal
    iptal_neden   varchar(200)
);
```

Ayrıca imzalı PDF **doküman deposunda** saklanır (15 yıl) ve değiştirilemez olarak işaretlenir.

## Uç önerisi

| Uç | İş |
|---|---|
| `POST /api/lab/rapor/{id}/imza-hazirla` | PDF üret, özeti dön (imzalanacak veri) |
| `POST /api/lab/rapor/{id}/imza-tamamla` | Aracın döndürdüğü imzayı göm, TSA damgası al, doğrula, kilitle |
| `POST /api/lab/rapor/toplu-imza-hazirla` | Seçili raporların özetleri |
| `GET  /api/lab/rapor/{id}/imzali-pdf` | İmzalı PDF |
| `GET  /api/dogrula/{belgeNo}` | Kimlik doğrulaması gerektirmeyen doğrulama sayfası |

Kural (§3.2 ile aynı ruh): **imza sunucuda doğrulanır**. İstemciden gelen "imzalandı" bilgisine
güvenilmez; sunucu imzayı sertifika zinciri + iptal listesi (CRL/OCSP) ile doğrulamadan raporu
imzalı saymaz.
